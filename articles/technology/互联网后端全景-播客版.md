# 互联网后端全景：一个经典互联网公司有哪些模块

> 播客版脚本 · 约 10 分钟

---

【开场】

你好，欢迎收听今天的节目。

如果你是做技术的，或者你正准备踏入互联网行业，你有没有想过一个问题——一个像模像样的互联网公司，它的后端到底长什么样？有哪些模块？每个模块是干嘛的？

你可能每天都在跟其中一两个模块打交道，但如果让你把整个后端的拼图拼出来，好像又没那么容易。

今天这期节目，我就带你把这张拼图一块一块拼起来。不管你是前端想转全栈，还是后端刚入行想看清全貌，又或者你根本不写代码、只是想了解互联网公司的运转逻辑——这期节目都适合你。

好的，我们开始。

---

【第一部分：入口——流量从哪来】

首先我们从一个最基本的问题开始：用户是怎么用上你们家产品的？

答案听起来很简单——打开网页、打开 App，对吧？但这只是其中一种。实际上，一个互联网公司的后端面对的是三类"入口"。

第一类，**客户端**，也就是普通用户。Web 网页、iOS 和安卓 App、电脑上的 PC 客户端，这些都属于客户端。你是从什么设备上来的，后端就通过对应的入口接待你。

第二类，**机器人**。哎，不是那种物理机器人，是平台上的 Bot。比如你用过飞书吧，飞书上有各种各样的机器人，你可以自己编程做一个，实现飞书本身没有的功能。这些机器人的背后也是后端在支撑。

第三类，**第三方**。你肯定遇到过——用抖音账号登录一个 App，或者用微信扫码授权。这种跨平台的跳转和认证，就是后端跟第三方系统的对接。

好，不管用户从哪个门进来，你都可以把他们理解为四个字：**就是流量**。

流量进来之后，它不会直接打到你的业务系统。它要先过两道关。

第一道叫**流量平台**。这个平台干什么呢？很简单——管流量的。正常用户是流量，黑客攻击也是流量，有人写脚本刷你们的优惠券，那也是流量。流量平台要把这些乱七八糟的东西识别出来、清洗掉。

还有一个场景——你们公司突然搞了个大促，用户量暴涨，流量平台要能帮你限流，保护后端不被冲垮。当然，如果你用的是阿里云这种第三方的流量清洗服务，我得提醒你一句：**清洗费挺贵的**。

过了流量平台，第二道关叫**网关层**。网关你可以把它理解为后端所有服务的统一大门。它不干业务，但它会帮你统计——哪个接口被调得最多、成功率是多少、哪个服务响应慢了。这些数据是后端优化的依据。网关还能做缓存，减轻下游压力。

好，过了这两道关，流量才算真正进入了后端的核心地带。

---

【第二部分：钱和用户——一家公司怎么活】

我们接着聊核心业务。一家公司要活下去，最关心什么？两件事：**钱**和**用户**。所以我们先说钱。

后端跟钱相关的系统，至少有三个。第一个是 **To B 商家平台**，服务企业客户的，比如商家入驻、资质审核，这些都需要一个系统来管。第二个是**对账平台**，钱进进出出，你不能对不上账。第三个是**支付系统**，对接银行、微信支付、支付宝，处理抽奖、履约、付款这些流程。

我在这多说一句——当你们公司的用户量到了一定规模，真的是什么人都有。有些人专门来薅羊毛，你们推出一个抽奖活动，他用脚本把奖品全抽走，然后再挂到你们的平台上加价卖给普通用户。这种情况很多公司做法是——**共存**。因为没这些人，你的东西可能还真卖不完。

还有一种更恶劣的，有人利用你们的平台**洗钱**。这个就跟待会要说的风控系统有关了，先按下不表。

好，钱说完了，我们来说用户。

对用户，公司的终极目标有两个：**增长**和**转化**。用户量越来越多，掏钱的比例越来越高。怎么做呢？靠**营销平台**。

营销平台日常做的事情包括：配置各种促销活动、跟第三方合作搞联合引流。但是光有活动不够，你还需要两样东西。

第一，**审核系统**。你想，平台用户多了以后，有人在里面搞诈骗、发色情内容，你不管的话，那就等着被约谈整改吧。前面说的拼多多算是大公司了吧，该来的照样来。

第二，**数据报表**。你做营销不能瞎做。今天多少用户登录了？他们干了什么？买了什么？哪个道具卖得好？哪个根本没人看？这些数据每天都要出来，驱动你的运营策略。

还有一套叫 **BI 展示**的东西——其实就是给老板看的大屏。老板要知道公司今天怎么样了，这个数据得有地方呈现。

---

【第三部分：数据和风控——看不见的基石】

下面我们聊一个"看不见但无处不在"的东西——**数据**。

在任何互联网公司，数据平台都是重中之重。而且它是使用面最广的系统——普通用户查自己的年度报告，产品经理看功能效果，运营看活动收益，老板看全局。大家都离不开它。

数据平台底下的基础设施有哪些呢？几条线给你捋一下。关系型数据库，比如 MySQL，存你的核心业务数据。分析型数据库，比如 ClickHouse，跑报表和复杂查询。对象存储，存图片、视频、静态资源。CDN，把静态内容分发到离用户最近的节点上，加速访问。

还有一个细节——你们公司的设计师做的各种图，那些都是静态资源，也要存在对象存储里。开发资源有限的时候，产品经理和设计师可能会变着法子自己动手改一些东西，来绕开开发排期。从开发的角度来说，我还挺赞同的——毕竟开发就那几个人，资源是真的不够。

好，说完数据，聊一个这几年才火起来的模块：**风控系统**。

前些年很多公司没有专门的风控。后来安全事故越来越多，大家纷纷建起了自己的风控部门。

风控系统主要干这些事：审核用户名和头像，不能让人起一些违反社会价值观的名字，头像也不能乱来。然后是实名认证——绑身份证、绑手机号，一人一号，提高违法成本。再然后监控资金往来——你这个号进进出出特别频繁、明显不正常，系统就会自动封禁。

还有消息审核——你的产品如果允许用户之间聊天，那发出来的内容就得过一遍。可以机器审，也可以人工审，或者两层都来。

【第四部分：代码怎么变成服务】

到目前为止，我们说的都是软件层面的设计。现在我们要把代码真真正正地跑起来——这就到了工程基础设施。

首先你需要一个 **CI/CD 流水线**。简单说，就是把你在电脑上写好的代码，变成服务器上能跑的服务。它会给你提供线下环境、预上线环境、线上环境——你在不同阶段去验证你的代码。它还会帮你打包——你是 Java 项目，给你 Java 环境；你是 Node 项目，给你 Node 环境；你是 Go，给你 Go。你只需要把代码交出去就行。

出了事它也能告警——上线失败了通知你，线上跑出一条慢 SQL 也通知你。

然后是**部署层**。你的代码打包好了，要跑到真实的机器上。你有几个选择：用阿里云这样的云服务器，租机器、交钱就行；自建机房，成本高、要维护、电费吓人；或者用 K8S 做容器集群管理。

还有一个很多人会忽略的东西——**域名**。你要跟腾讯、微信这些平台对接，人家要求你必须有正式备案的域名，没有域名，人家不认你。

---

【第五部分：后端通用组件——万变不离其宗】

最后一个板块，我来给你梳理一下，不管你去哪家公司做后端，你都会遇到哪些"固定组件"。

第一，**一门编程语言**。现在其实什么都行——Java、Go、Python、Node.js 都可以。因为说白了，只要有一个网络框架，能让你在应用层或者传输层做交互，能选协议，就能做后端。

第二，**数据库**。关系型的、非关系型的、内存型的、外存型的、时序的、分析的——这几类都见过了，基本上就全了。

第三，**异步任务**。有些操作不是用户点一下就要立刻返回的，你可能需要延迟执行或者定时执行。

第四，**消息队列**。当两个系统你不想让它们直接耦合在一起，中间放一个 Kafka 或者 RocketMQ，解耦、削峰、填谷，一举多得。

第五，**对象存储**。文件切片上传这种事已经是上一代的方案了，现在直接用对象存储服务。

第六，**支付底座**。现在基本没有人直连银行了，都是对接微信支付或者支付宝的 API。

第七，**流量网关**。灰度发布、金丝雀发布、限流，这些都是网关的活。

好，以上这七个组件，你只要理解它们分别是解决什么问题的，然后对其中一两个的实现有深入理解——你会发现，用什么语言、在哪家公司做后端，底层逻辑都是一样的。万变不离其宗。
